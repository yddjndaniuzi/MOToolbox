# MOtoolbox 多业务发布会平台工程方案

## 1. 建设目标

将现有手机发布会专用链路改造成“通用媒体处理底座 + 可配置领域包 + 可配置任务类型”的平台。当前支持：通用科技、手机/消费电子、汽车、大模型、机器人、芯片/半导体。

核心验收指标：专名准确率、关键事实召回率、无依据新增率、证据时间码覆盖率、领域识别准确率、录制完整率。

## 2. 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| capture | 下载、录制、抽帧、完整性 | 行业判断 |
| transcript | 字幕选择、ASR、置信度 | 摘要 |
| domains | 领域注册、识别、指标和提示词配置 | 模型调用 |
| fact ledger | 实体、数值、单位、证据时间码 | 文风加工 |
| brief | 领域化基础稿骨架和证据对齐 | 编造缺失事实 |
| refine | 按领域和任务模板生成成稿 | 修改原始证据 |
| coverage | 各阶段事实去留和质量门禁 | 内容创作 |

## 3. 数据契约

任务 manifest 新增：

```json
{
  "domain": {
    "requested": "auto",
    "resolved": "automotive",
    "confidence": 0.91,
    "signals": ["智驾", "CLTC", "车型"]
  },
  "task_type": "business_review"
}
```

事实账本 `fact_ledger.json` 的事实记录：

```json
{
  "id": "fact-0001",
  "domain": "automotive",
  "type": "range",
  "value": "820",
  "unit": "km",
  "timestamp": [1820.4, 1828.7],
  "source_text": "CLTC 续航达到 820 公里",
  "confidence": 0.9,
  "status": "extracted"
}
```

## 4. 领域包规范

每个 `pressconf/domains/<id>/domain.json` 定义：显示名、识别关键词、章节结构、事实类型、领域提示词和 ASR 热词。新增领域不应修改核心流程代码。

## 5. 任务类型

- `faithful_transcript`：忠实整理，不删事实，不做行业判断。
- `launch_notes`：按议题生成发布会速记。
- `business_review`：行业帮看，输出判断、风险和商业含义。
- `fact_extract`：以事实账本和参数/价格表为主。

## 6. 迁移路径

1. 建立领域注册器并把手机规则迁入领域包。
2. Capture UI 写入领域和任务类型；ASR 使用领域热词。
3. ASR 后二次识别领域并固化到 manifest。
4. 基础稿和精加工改为领域章节/提示词驱动。
5. 建立跨领域事实账本及覆盖审计。
6. 每领域使用至少 3 场真实发布会建立回归集。

## 7. 质量门禁

- 自动领域置信度低于 0.45 时回退 `generic`。
- ASR 可疑片段必须进入质量报告。
- 关键数字必须携带原文和时间码；冲突值不得静默纠正。
- 精加工后输出事实保留率；不得只以文稿可读性作为验收依据。
- 直播录制不完整时禁止进入 ASR。

## 8. 当前实施状态

已落地：

- 领域注册器及五个首批领域包；
- 自动识别、置信度、命中依据和人工覆盖；
- 发布会采集与评测视频帮看的领域选择；
- 领域化 ASR 热词、基础稿章节、精加工角色和任务模板；
- 忠实转写、发布会速记、业务帮看、专项事实抽取四类任务；
- `fact_ledger.json` 事实账本和 `coverage_report.json` 覆盖审计；
- 手机业务帮看旧结构兼容；
- PyInstaller 领域包及热词资源打包。

后续增强项：

- 接入 PPT OCR，建立“ASR 数字 ↔ 画面数字”冲突检测；
- 对事实账本增加模型辅助的主语、限定词和比较对象抽取；
- 为每个领域建设 3–5 场金标回归集和指标看板；
- 增加后台领域包编辑、版本管理与灰度发布；
- 按领域训练关键帧页面分类器（价格、参数、架构、Demo、权益）。
