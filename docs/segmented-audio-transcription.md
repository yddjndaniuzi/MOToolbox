# 长音频转写修复（2026-09-15）

MediaTek 发布会录音长 7515 秒。旧 MLX 转写语言检测为 en，后段连续输出短句“I'm out.”；13 批总结调用均正常结束，所以文本分段不能解决这次音频证据缺失。

MLX 和 faster-whisper 对超过 180 秒的音频使用独立的 180 秒核心区间，两侧各加最多 3 秒上下文。语言按块检测（显式 MOTOOLBOX_ASR_LANGUAGE 优先），关闭前文继承。按字幕中点归属区间，并恢复全局时间戳。

跨字幕重复、文本过稀、非有限置信度或严重解码质量异常会触发 60 秒子段重试，重试移除热词提示；未显式指定语言时参考最近一个通过质量检查的片段语言。仍异常的区间记录在 quality.json 的 unresolved_intervals，并在字幕和简报中明确披露，同时保留该区间内通过检查的字幕；不能据此推断发布会结束。短语重复可能来自音乐或真实口号，故标记为待核实，而非认定没有语音。混合语言切换仍需人工核实。

长录音的旧自动转写缓存失效；新版存在待核实区间的缓存也会重转。官方/外部 source.srt、source.vtt 保留。旧文件在新转写成功前保留。音频分段版本写入 asr_pipeline_version；总结分段版本升至 3，避免复用错误的“散场”结论。

文本覆盖率只衡量可用字幕被消费的比例，不是音频识别完整率。该策略降低长音频失真传播，并暴露失败区间，不能保证所有语音均识别准确。

验证：tests/test_asr_segments.py 覆盖跨字幕短句循环、NaN、局部重试、全局时间轴和片尾、待核实标记、旧缓存失效；并运行既有转写与分段总结回归测试。
