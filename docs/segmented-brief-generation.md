# 长发布会简报分段生成

2026-09-10：华为 Mate XT 2、苹果秋季发布会的原始转写均覆盖片尾，旧简报分别停在第 21/58、22/26 章。旧逻辑一次生成全文，上限 16,000 tokens，未检查模型停止原因；现有日志不能直接证明历史调用达到上限，但输出断在半句且转写完整，符合输出截断特征。

## 当前流程

- 超过 4 个章节或原始转写超过 24,000 字符时启用分段；短稿保留单次生成。
- 沿用基础稿三分钟章节及原编号，每批最多 4 章、15 分钟、16,000 字符转写正文，通常约 12 分钟。超长单章拆为片段，最终合回原章节。相邻段附带前文末尾 300 字符，仅用于理解衔接。
- 全部转写正文按顺序进入各批，无 10 万字符抽样。每批返回完整详情和供概述使用的事实索引；索引最多 6,000 字符。
- 概述、产品概要和表格单独生成。索引超过 40,000 字符时分层汇总索引；详情始终由程序拼接，不再次全文重写。图片按原章节编号恢复。
- 该覆盖率表示原始文本进入处理的比例，不代表模型保留了所有事实。事实保留仍可查看 coverage_report.json，并人工核对疑似 ASR 错误。

## 完整性和恢复

- Anthropic 要求 end_turn 和 message_stop；OpenAI 兼容接口要求 finish_reason=stop。max_tokens、length、缺少停止原因等均报错，不把残稿写成正式稿。
- 所有章节必须按原顺序完整出现；漏章、重复章、格式错误均拒绝替换正式稿。
- 成功批次及模型用量写入 refine_chunks/<run_id>/，失败批次保留 partial.txt，自动重试一次。再次发起相同生成会复用成功结果。
- 缓存键包含源稿、原始转写、编辑要求、模型、接口地址和流程版本，不包含 API key。材料或要求改变会启用新缓存。
- brief_refined.partial.md 保存当前已完成的详情。只有全部步骤通过才原子替换 brief_refined.md。Web 工作流随后同步 brief_current.md。
- refine_meta.json 的 generation 字段及各批 run.json 保存批次、章节、停止原因和接口实际返回的 token 用量；未返回用量的服务不会伪造 token 数。
